参与 GitHub 贡献

这本绿皮书欢迎被使用，也欢迎被纠正、补充和继续做大。

把一次使用，变成下一次改进

千问办公绿皮书是一个公开维护的静态网站。你可以阅读源码、复现案例、指出错误，也可以把自己的脱敏工作流程整理成案例，通过 GitHub Pull Request 参与维护。

公开源码欢迎提 PR先脱敏，再提交

三种参与方式

01 · 发现问题

提交一个可复现的问题

说明页面、位置、现象、预期效果和复现步骤。涉及截图或资料时，请先移除个人信息、公司信息和敏感数据。

02 · 修改内容

提交 Pull Request

Fork 仓库后修改 HTML、CSS、图片说明或案例资料，提交 PR 时写清楚改了什么、为什么改，以及是否已经本地检查。

03 · 分享案例

补充一条真实工作流

优先提供具体麻烦、输入资料、使用指令、AI 产出、人工判断、最终结果和验收边界。不要把一次生成包装成未经验证的成功。

案例提交的最低标准

工作语境谁在什么岗位，遇到了什么具体麻烦。
原始资料提供可脱敏、可复现的输入材料。
过程证据保留指令、截图、中间产出和修改过程。
人工边界写清楚哪些判断不能交给 AI。
交付结果说明最后交出了什么，以及如何验收。

提交前请先做脱敏

删除姓名、手机号、邮箱、客户名称、合同金额、内部链接、账号信息和未公开文件。案例中的公司、人物、截图与数据应当允许公开展示；无法确认时，宁可只提交结构和方法。
