# 案例优先与去 AI 味改版规格

## 定位

千问办公绿皮书是一份“个人工作提效手册”：默认读者已经会使用千问办公，正文从真实工作麻烦、交付结果和做事过程开始，而不是从软件功能和官方教程开始。

## 信息架构

主导航顺序固定为：

1. 首页：说明这本绿皮书解决什么工作问题；
2. 实战案例分享：黄金案例小明的交付升级记 + 其他并行案例；
3. 任务速查：按工作结果寻找入口；
4. 方法论：GTD、会做 × 想做、人机分工；
5. 官方教程：Phase 1–3 与基础功能，作为补充入口；
6. 关于与贡献。

`完整目录`、`路径总览`、`Phase 1–3` 保留页面与链接，但不再占据主导航的前置位置。

## 前台表达

案例页面优先使用普通工作语言，方法论页面再使用专业术语。统一将“AI 主做 / 人主做”改为“千问可以先接手 / 你需要判断和拍板”，将“证据链”解释为“每个数字都能找到出处”，将“真实推演证据”解释为“这件事实际是怎么做出来的”。

## 案例阅读顺序

每个案例按“工作现场 → 交付目标 → 做事过程 → 千问先接手 → 你来判断 → 过程截图 → 最终结果 → 可复用做法”展开。证据截图、下载附件和现有案例事实不删除，只调整入口和周边叙事。

## 非目标

- 本轮不删除任何案例证据、原始资料、截图或交付物；
- 本轮不重写每个案例的事实内容；
- 本轮不把官方教程内容伪装成绿皮书原创方法；
- 本轮不新增复杂交互。
