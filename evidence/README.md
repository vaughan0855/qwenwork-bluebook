# 千问办公蓝皮书：黄金案例素材协作说明

你负责在千问办公里完成真实推演、截取过程并导出产出物；我负责把这些素材嵌入网页并统一叙事。

## 文件放置位置

把截图放在本目录，按章节和用途命名：

```text
ch1-input-01.png       # 输入资料组，可以有多张
ch1-prompt-01.png      # 使用指令组，可以有多张
ch1-output-01.png      # AI 产出组，可以有多张
ch1-review-01.png      # 人工判断或修正组，可以有多张
ch1-result-01.png      # 最终结果组，可以有多张
```

每章固定五类证据包，不是五张截图。每一类截图数量不限，也可以暂时没有截图；先放已经截好的，缺少的我会保留“待补素材”位置。

注意：`review` 只有在真实的人检查、质疑或修改 AI 输出后才放；`result` 只有在确实形成了最终交付物后才放。AI 输出本身不能同时充当人工判断和最终结果。比如第一章当前是“输入资料 2 张、使用指令 1 张、AI 输出 4 张、人工判断 0 张、最终结果 0 张”，页面会如实显示到这一步。

汇报稿建议放在：

```text
客户成功体系升级方案-10页汇报初稿.pptx
客户成功体系升级方案-10页汇报-待确认版.pptx
```

## 每章固定五项

| 项目 | 要回答的问题 |
| --- | --- |
| 输入资料 | 小明手里有什么原始信息？ |
| 使用指令 | 他在千问办公里具体要求什么？ |
| AI 产出 | 千问实际返回了什么中间结果或文件？ |
| 人工判断 | 小明检查、修正或拒绝了什么？ |
| 最终结果 | 这一步把任务推进到了哪里？ |

截图放入后，不需要你直接修改 HTML。告诉我“哪些文件已经放好”，我会完成页面接入、说明文字和移动端检查。

本次 8–23.png 这批按现有推演顺序自动接入：8–11 为第三章资料地图，12–14 为第四章证据体检，15–23 为第五章数据核验与总监挑战。你不需要把它们改成章节命名。

第六章的 PPTX 也由我自动渲染为 `ch6-output-01.png` 至 `ch6-output-10.png`，Update 版会渲染为 `ch6-update-01.png` 至 `ch6-update-10.png`。原始文件保留在本目录，页面会同时提供下载入口。

## 独立案例素材

非“小明的交付升级记”的新案例，单独放进对应目录，例如：

```text
case-prospectus/
├── 2-1.png                         # 原始研究指令
├── 2-2.png                         # 研究口径澄清
├── 2-3.png                         # AI 产出摘要
├── 证据底稿与验证矩阵.md             # 研究底稿 / 复核依据
└── 交付物.pptx                      # 面向听众的最终表达文件
```

独立案例页面仍然按“任务 → 资料与来源 → AI 处理 → 交付物 → 人工复核边界”来组织。案例已经形成 AI 交付，不等于其中每个外部数字都已经被人工核验；如果还没有回到原始报告逐项确认，页面应标为“待人工复核”。
