# 08 人工验收清单｜AI 硬件竞品日报（候选版）

> 用途：日报定稿与推送前的逐项把关。全部"必过项"通过后方可进入正式推送。
> 原则：AI 只做来源定位、字段结构化与分级；是否值得列为 P0、影响定性、是否推送由人工拍板。
> 本轮证据：7-6～7-9 展示清单与推送闸门的形成过程；7-10 展示钉钉客户端收到一次消息。该截图不等于定时任务和全链路自动化已验收通过。

## 一、内容验收（必过项）

- [ ] 每条重点新闻都有**来源、日期、对象、事件类型**（缺任一 → 移出重点区，降级为待核验）
- [ ] **已确认 / 多源 / 待核验**三层分层展示，待核验不进入结论区
- [ ] 未把"可能/据称/网传"改写成"已经"；未把可能影响写成事实
- [ ] 未从单条新闻推出销量、市场份额或用户增长
- [ ] 未把 AI 生成的影响判断当作企业战略事实
- [ ] 三个类目都能找到内容，或明确写"今日无新增"（不留空类目）
- [ ] 每条重点变化都有下一步行动与核验责任人（无悬空条目）
- [ ] 传闻与官方确认未被合并为同一条"事实"

## 二、去重与来源验收

- [ ] 同一官方公告被多家转载 → 只保留官方源，媒体记为"补充来源"
- [ ] 同一事件有新信息 → 记为"更新"，未重复生成相同条目
- [ ] 无来源转载、标题党、打不开的截图未被用作确认依据

## 三、推送验收

- [ ] 钉钉/飞书消息在手机端 **2 分钟内可读完**
- [ ] 链接可追溯到完整日报与原始来源
- [ ] 待核验/高风险内容未进入未经人工确认的正式推送
- [ ] 推送目标（群 / 机器人归属）、时间与时区已确认
- [ ] 已确认"是否允许待核验内容进入群消息"
- [ ] 已确认失败处理：访问失败时重试 / 跳过 / 报警，以及失败通知发给谁
- [ ] 已确认"每日无新增是否推送无重大变化"

## 四、案例页面验收（对应 05 验收标准）

- [ ] 明确标注当前使用的是**资料模板**还是**实测快照**
- [ ] 未宣称已完成定时任务、推送或零值守运行
- [ ] 至少留下：一份日报、一次人工筛选记录、一次推送验证记录

## 五、放行结论（人工填写）

| 项 | 结果 |
|---|---|
| 是否可定稿 | 可 / 需返工（列明条目） |
| 是否可推送 | 可推送 / 仅推已确认项 / 暂不推送 |
| P0 是否认可 | 认可 / 调整为 ___ |
| 待核验处理 | 保留待查 / 指派 ___ 于 ___ 核验 |
| 验收人 / 日期 | |
