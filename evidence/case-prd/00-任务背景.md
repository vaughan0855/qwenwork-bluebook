# 产品需求 → 设计简报 → PRD：任务背景

> 资料性质：合成实验资料，用于验证“千问办公能否把访谈、反馈、会议决策和技术约束串成一条可评审的需求链”。不代表任何真实公司或真实用户。

## 角色

你是产品经理，负责把一个跨销售、客户成功和技术的模糊需求推进成一期可评审的 PRD。

## 触发任务

产品负责人说：

> 客户跟进经常断掉，先做一个客户回访记录和下次跟进提醒的功能。下周评审前把需求、用户故事、设计简报和 PRD 都准备好，但一期不要做得太重。

## 工作麻烦

- 访谈中混有抱怨、愿望和真正需求；
- 销售希望快速记录，客户成功希望有逾期提醒，技术限制了一期范围；
- 会议纪要中有未决事项，不能直接当成已确定需求；
- PRD 不只是把所有意见抄在一起，还要说明取舍和验收方式。

## 期望交付

1. 需求澄清与冲突清单；
2. 用户故事和优先级；
3. 面向设计师的设计简报；
4. 一期 PRD、非目标和验收标准；
5. 待产品负责人拍板的问题。
