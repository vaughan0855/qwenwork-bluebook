# 千问办公第一轮指令

请阅读资料池中的任务背景、访谈记录、评审会议纪要、用户反馈、现有能力与约束、验收标准，帮我推进“客户回访记录和下次跟进提醒”这个需求。

请先不要直接写完整 PRD。先输出：

1. 这个需求真正要解决的用户问题是什么？
2. 涉及哪些角色，他们的目标和冲突分别是什么？
3. 将资料分成：已确认事实、用户愿望、产品推断、技术约束、待拍板事项；
4. 建立“证据 → 用户问题 → 用户故事 → 功能候选”的追踪表；
5. 建议 P0 / P1 / 不做的范围，并说明依据；
6. 列出至少 5 个需要产品负责人确认的问题；
7. 哪些内容不能在一期 PRD 中承诺？

完成这轮判断后，再输出一版候选交付：

- 需求澄清摘要；
- 用户故事与优先级；
- 面向设计师的设计简报；
- PRD 目录和关键页面/状态说明；
- 每条 P0 需求的验收条件；
- 待确认清单。

要求：不要把访谈中的愿望直接写成需求；不要把会议纪要中的“尚未决定”当成已确认；严格遵守一期不读取聊天记录、不做自动客户分层的范围边界。
