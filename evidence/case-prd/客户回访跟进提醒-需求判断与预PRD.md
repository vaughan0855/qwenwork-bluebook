## 客户回访记录与下次跟进提醒 · 需求判断与候选交付（预 PRD 稿）

> 本文基于 case-prd 资料池（任务背景 / 访谈 / 评审纪要 / 用户反馈 CSV / 现有能力与约束 / 验收标准）推导，全部结论可溯源。
> 标注约定：**【事实】**资料已明确共识；**【愿望】**访谈里的说法，尚未翻译成需求；**【推断】**我按证据做的合理推导，可被推翻；**【约束】**技术/边界限制；**【待拍板】**未决定，不得当作已确认写入 PRD。
> 一期硬边界（不越线）：不读取聊天记录、不做自动客户分层。

### 一句话结论

真正的用户问题不是"缺一个回访记录功能"，而是**"销售/客户成功跟客户聊完之后，下一步动作没有被记录、被认领、被到点提醒，于是跟进断档、客户觉得失联"**。一期应做一个**贴着客户页、低录入成本的"跟进闭环最小单元"**（记一条下一步 + 定一个负责人和提醒日期 + 到期站内提醒 + 逾期可见），把分层、自动读取、周期推荐、主管看板全部推到后续。

# 第一部分：判断轮

## 1. 这个需求真正要解决的用户问题

把"客户跟进经常断掉"拆成三层，功能候选分别对应：

| 层次 | 真实问题 | 证据 | 若不解决会怎样 |
|---|---|---|---|
| 记录层 | 上次沟通的上下文没沉淀，换人/隔几天就断片 | F03、共识#2 | 客户重复被问、体验差 |
| 行动层 | 聊完没把"下一步"固化成一个带负责人和日期的动作 | F01、共识#1/#2 | 最核心痛点：没有下一步 |
| 提醒层 | 到了该跟的时间没人提示，逾期了也没人发现 | F04、共识#3 | 失联、客户以为被遗忘 |

**关键区分**：产品负责人原话是"先做回访记录和提醒"，但访谈证据指向的是**"行动闭环 + 轻量提醒"**，不是"信息登记台账"。一期价值锚点应放在行动层与提醒层，记录层只做够用即可。同时【愿望】"记一句话""别弹一堆""标红"是**手段表达**，不是需求本体，需转译成"低录入成本""提醒噪声可控""逾期状态可见"三条设计原则。

## 2. 涉及角色：目标与冲突

| 角色 | 核心目标 | 主要痛点 | 与其他角色的冲突 |
|---|---|---|---|
| 销售代表 | 少填、快记、别被弹窗打扰 | 聊完忘写下一步（F01/F02/F08） | 与**客户成功**冲突：要信息完整、逾期标红、周期各异=更多字段/更多提醒 |
| 客户成功 | 上下文可见、逾期别失联、周期可差异化 | 看不到上次内容和下次动作、逾期无提醒（F03/F04） | 与**销售**冲突：录入负担与提醒噪声；与**技术**冲突：周期/健康度自动化的诉求 |
| 销售主管 | 团队里哪些客户"没后续动作"一眼可见 | 管理视图缺失（F05，中频中严重） | 与**一期共识**冲突：会议未纳入；与**销售**冲突：数据暴露感 |
| 产品负责人 | 一期做轻、不接外部聊天、分层不自动化 | 范围易被愿望撑爆（F07） | 与所有"愿望"方冲突：负责砍 |
| 技术 | 只复用现有能力、不新增重接口 | 无聊天读取、无多人协同编辑（F06） | 与"自动摘要""自动推荐""共同编辑"类诉求冲突 |

**主矛盾**：销售要"轻"、客户成功要"全和醒"——一期靠**字段默认精简 + 高级字段折叠**、**站内提醒 + 频控/合并**来调和，而不是二选一。

## 6. 需要产品负责人确认的问题（≥5）

1. **数据形态（P-a）**：跟进记录是"每客户一条最近记录"还是"客户下的跟进任务列表、可多条未完成并存"？——决定列表页、完成逻辑与逾期判定口径。
2. **完成定义（P-b）**：标记"完成"是否强制写结果说明？还是勾选即可、说明选填？——影响验收与录入成本。
3. **日期回填（P-c）**：提醒日期是否允许选早于今天（用于补录已逾期的历史动作）？若允许，逾期态如何展示？
4. **编辑权限（P-d）**：谁能改谁的跟进记录？同组销售是否互改、主管是否可改？涉及 C2 无协同编辑，冲突时以何为准（如"最近保存者胜 + 变更留痕"）？
5. **逾期视觉阈值（P-g）**：标红/逾期=“提醒日已过且未完成”即触发，还是给 N 天宽限期？"日"按自然日还是提醒时刻？
6. **提醒频控与关闭（P-e）**：逾期站内提醒每天一次、当日合并、还是仅首次？提供哪些处理动作（稍后提醒 / 忽略 / 标记完成）？
7. **一期是否含任一"按客户周期"（P-f）**：是完全统一手动选日期，还是允许每客户设一个默认间隔（仍不自动推荐）？
8. **主管视图归属（P-h）**：F05 主管视图一期就要（哪怕只读），还是明确推到 P1？

## 7. 一期 PRD 中不能承诺的内容

以下任何一项，即便在访谈/会议里以"愿望"或"未决"出现，**一期 PRD 正文与验收条件里都不得写成承诺**：

- 自动读取微信/钉钉/邮件并生成沟通摘要（仅允许人工填写/粘贴摘要）。
- 自动客户分层、健康度评分、自动推荐回访问隔（周期一期为手动）。
- 逾期提醒自动发送钉钉/短信/邮件到外部或跨系统推送（一期仅站内）。
- 面向客户本体的任何外部通知。
- 多人实时协同编辑与冲突合并。
- 所有"待拍板"事项的具体取值：在负责人决策前，PRD 用"取决于决策点 P-x"的条件化表述占位，**不得把纪要中的"尚未决定"写成已确认规则**。

# 第二部分：候选交付（预稿，可评审）

## A. 需求澄清摘要

**背景**：客户跟进常断档，一期在现有客户台账内补齐"跟进记录 + 下次提醒"的轻闭环，做轻、不扩范围。

**要解决的唯一核心问题**：让销售/客户成功在跟客户沟通后，用最少的录入成本把"下一步动作 + 负责人 + 提醒日期"固化下来，并在到点/逾期时通过站内提醒让人发现，从而减少失联式断档。

**一期设计三原则**（由愿望转译而来）：
- 低录入优先：一个必填即可起步，高级字段折叠，不强迫填十个字段（W1/W2）。
- 提醒有效但不吵：站内为主、当日合并、处理动作明确（F08/W3）。
- 上下文与状态可见：最近一次沟通摘要 + 下次动作 + 逾期态一眼可见（F03/F04/W4）。

**核心对象**：`跟进记录（Follow-up）`，挂在客户下，承载五要素（A2）。

**一期非目标（写死）**：见第 7 项清单——不读聊天、不自动分层/推荐、不外发通知、不做协同编辑。

**主要依赖**：复用客户台账、文本/日期/状态枚举、站内提醒、CSV。

## C. 面向设计师的设计简报

### C1. 目标用户与待完成任务
一线销售代表（重录入成本、怕被打扰）与客户成功（重要上下文、怕失联）为双主用户；销售主管为次要用户（P1）。Jobs：**低成本记录 → 到点被提醒 → 一眼发现逾期 → 标记完成**。

### C2. 设计目标与原则
- 三步内完成一条跟进记录（入口—下一步动作—日期）。
- 最少必填、高级可选，默认折叠。
- 提醒克制：当日合并、视觉分级（今日/逾期）。
- 状态可读：未开始 / 进行中 / 已完成 / 逾期，四态一眼分得清（逾期视觉规则待 P-g）。

### C3. 关键页面
- **页面1 · 客户详情页 - 跟进模块**：顶部展示"最近一次沟通摘要 + 下次动作 + 负责人 + 提醒日 + 状态"；下方"跟进历史"列表（列表形态待 P-a）。
- **页面2 · 快速添加跟进（内联浮层/抽屉）**：1 个必填（下一步动作 或 沟通摘要其一，取决于 P-a/P-b），其余（负责人默认=当前用户、提醒日期、沟通摘要、结果说明）折叠可选。
- **页面3 · 站内提醒中心 / 通知角标**：到期与逾期聚合，支持"标记完成 / 稍后 / 忽略"（动作集待 P-e）。
- **页面4 · 跟进列表视图（P1 主管视图）**：按"无后续动作/逾期"筛选 + CSV 导出（US-07）。

### C4. 状态矩阵（每页需覆盖）

| 状态 | 跟进模块 | 快速添加 | 提醒中心 |
|---|---|---|---|
| 空状态 | "暂无跟进，记录第一条"引导 | — | 无未处理 |
| 录入中 | — | 必填校验、折叠展开、默认负责人 | — |
| 成功 | 新记录置顶/最近更新 | 保存后收起 | 生成到期项 |
| 到期 | 下次动作高亮 | — | 站内提醒 |
| 逾期 | 状态标"逾期"（**视觉/阈值待 P-g**） | — | 逾期分组置顶 |
| 已完成 | 灰/绿标记、移出待办 | 结果说明（**是否必填待 P-b**） | 从待办消失 |
| 异常 | 无权限他人记录（**权限待 P-d**）只读 | 日期早于今天（**待 P-c**）的提示 | 提醒失败降级 |

### C5. 异常与边界场景
无权限编辑他人记录、提醒日期早于今天、逾期判定跨天口径、多条未完成并存（若 P-a 允许）、提醒当日重复。

### C6. 设计禁区（避免把"非目标"画进 UI）
不做聊天内容自动填充区、不做客户分层标签/健康度仪表、不做自动周期推荐提示、不做面向客户的外部通知配置、不做多人协同光标/实时并发编辑。

### C7. 文案与语气
轻提示、不指责；提醒文案给动作入口而非制造压力（如"该跟进 X 客户了 →"而非"你已逾期未完成！"）。

## D. PRD 目录与关键页面/状态说明

**《客户回访记录与下次跟进提醒 · 一期 PRD》目录**

1. 背景与目标（含"要解决的唯一问题"、成功度量口径）
2. 范围：一期做什么 / **非目标（一期不做清单）** / 后续（P1）
3. 用户与角色、权限矩阵（依赖 P-d 待拍板，先占位）
4. 核心概念与数据模型：`跟进记录` 五要素字段表（字段名/类型/是否必填/默认值/来源=复用 A5）
5. 交互流程：添加跟进 → 到期提醒 → 逾期发现 → 标记完成（主流程 + 异常流）
6. 功能需求（按 US-01…US-06 逐条，每条含验收条件）
7. 提醒规则（站内、频控、关闭动作；标 **P-e/P-g 待拍板**）
8. 状态与视觉规则（四态 + 逾期视觉，标 **P-g 待拍板**）
9. 权限与协同（单编辑者假设下，标 **P-d/C2**）
10. 依赖与约束（现有能力 A5、技术约束 C1–C4）
11. 度量指标与埋点（跟进覆盖率、逾期发生率、提醒处理率）
12. **待产品负责人确认清单**（P-a…P-h）
13. 附录：证据—需求追踪表

**关键页面/状态说明**：见 C3 页面清单 + C4 状态矩阵，PRD 第 5–8 节据此展开；凡标"待拍板"处，PRD 正文用条件句占位，不写死规则。

## E. 每条 P0 需求的验收条件（Given/When/Then）

> 凡涉及待拍板项，用"**取决于决策点 P-x**"的条件化表述，负责人决策后替换为确定值。

**US-01 快速添加跟进**
- Given 我在某客户详情页，When 我点击"添加跟进"并只填写必填项（下一步动作）后保存，Then 系统创建一条状态为"未开始"的跟进记录，且未强制我填写其余字段。
- Given 我展开高级字段，When 我补填沟通摘要/负责人/提醒日期，Then 记录保存对应内容，负责人默认为当前用户。

**US-02 负责人 + 提醒日期**
- Given 我在添加/编辑跟进，When 我选择提醒日期并保存，Then 记录携带该日期，且在到期日按提醒规则（见 US-04）产生站内提醒。
- Given 提醒日期可选早于今天，When 我选择过去日期保存，Then **取决于决策点 P-c**：允许并标记为逾期 / 阻止并提示。

**US-03 最近沟通与下次动作可见**
- Given 某客户已有跟进记录，When 我打开客户详情页跟进模块，Then 我看到最近一次沟通摘要、下一步动作、负责人、提醒日、完成状态；历史列表形态**取决于决策点 P-a**。

**US-04 到期提醒与逾期可见**
- Given 一条"未完成"跟进的提醒日期=今天，When 我登录/刷新，Then 我在站内提醒中心看到该条到期提醒。
- Given 一条"未完成"跟进已过提醒日期，When 我查看客户或列表，Then 该记录被标为"逾期"（视觉规则**取决于决策点 P-g**）。
- Given 同一天存在多条到期/逾期，When 提醒展示，Then 按当日合并呈现（频控口径**取决于决策点 P-e**）。

**US-05 标记完成**
- Given 一条"未开始/进行中/逾期"的跟进，When 我点击"标记完成"，Then 状态变为"已完成"、提醒从待办消失。
- Given 我标记完成，When 系统要求结果说明，Then **取决于决策点 P-b**：结果说明必填方可提交 / 选填可直接提交。

**US-06 编辑权限与协同（一期简化）**
- Given 我不是某条跟进记录的负责人，When 我尝试编辑，Then 按**待拍板 P-d** 的权限规则执行；一期在无协同编辑（C2）前提下，不做实时合并。

**（P0 提醒降噪基线）**
- Given 提醒中心展示，When 我选择"稍后/忽略/标记完成"任一动作，Then 该条不再于当前周期重复出现，动作集合**取决于决策点 P-e**。

## F. 待确认清单（汇总 · 供产品负责人拍板）

| 编号 | 问题 | 我的默认建议（可被推翻） | 影响的 US/验收 |
|---|---|---|---|
| P-a | 单条最近记录 vs 客户下多任务列表 | 建议**列表**（支持多条未完成），更贴合"看上次+下次" | US-03/04、数据模型 |
| P-b | 完成是否强制结果说明 | 建议**选填**，一期降低录入门槛 | US-05 |
| P-c | 提醒日期是否允许早于今天 | 建议**允许回填并直接判逾期**，减少补录摩擦 | US-02 |
| P-d | 谁能改他人记录 | 建议一期**负责人+主管可改、同组只读**，改动留痕 | US-06、权限矩阵 |
| P-e | 提醒频率与关闭方式 | 建议**当日合并 + 提供 完成/稍后/忽略** | US-04、提醒规则 |
| P-f | 一期是否含按客户自定义间隔 | 建议一期**统一手动选日期**，周期模板放 P1 | US-08 |
| P-g | 逾期视觉/阈值 | 建议**过提醒日次日 0 点即判逾期、红色标记，无宽限期** | US-04、状态视觉 |
| P-h | 主管视图一期是否要 | 建议**推 P1**（中频中严重、共识未纳入） | US-07 |

> 决策前，以上均以"待拍板"占位，不写入 PRD 为已确认规则；决策后回填 US 验收条件与设计状态视觉。
